# 大乐透分析网页项目规范

## 项目定位

本项目是一个本地单页应用，用于查询、分析和娱乐化选号。所有趋势、评分、选号理由都必须标注“仅供娱乐，不构成购彩建议”。应用不承诺预测准确性。

## 数据规范

- `dlt_history_FULL.md` 只作为原始归档、导入来源和导出格式，不作为运行时主数据源。
- `data/dlt-draws.json` 是唯一可信主数据源，前区和后区都保存为数字数组。
- `data/dlt-meta.json` 保存数据版本、总期数、最新期号、最新日期、来源和生成时间。
- 展示层负责把数字格式化为 `01`、`02`；数据层不得保存带前导零的字符串号码。
- 任何导入、同步、手动新增都必须经过校验：期号唯一、日期合法、前区 5 个不重复且在 `1-35`，后区 2 个不重复且在 `1-12`。

## 工程规范

- 单个业务文件控制在约 250 行以内；超过时拆分 hooks、utils、types、子组件或配置。
- 每个分析卡片独立一个组件文件，计算逻辑独立放在 `src/features/analysis/calculators`。
- 页面组件只负责布局、状态组合和路由式切换，不写具体统计公式。
- 新增功能优先复用 `src/domain` 的规则工具和 `src/data` 的解析校验工具。
- 文件命名使用语义化英文，组件使用 PascalCase，工具和计算器使用 camelCase。

## 目录职责

- `src/data`：数据加载、解析、导入导出、校验。
- `src/domain`：大乐透规则、中奖判定、号码格式化、统计基础工具。
- `src/features/query`：历史查询、号码检索、中奖检查。
- `src/features/my`：多组自选号码管理、本地存储、最新/指定期开奖检查、历史回看和简要分析。
- `src/features/analysis`：分析页面、卡片注册、分析卡片和计算器。
- `src/features/picker`：娱乐选号器和策略解释。
- `src/features/manage`：单期新增、批量导入、导出和数据健康报告。
- `src/components`：通用 UI 组件。
- `src/charts`：ECharts 封装组件。
- `scripts`：数据导入、导出、同步、校验脚本。

## 浏览器本地偏好

- 查询页通过“添加到我的号码”将当前选择存入“我的”清单，按长期关注号码去重；旧版查询单组存储只作兼容读取与迁移来源。
- 自选号码保存内容与开奖主数据分开，不上传、不修改 `data/dlt-draws.json`，也不会随项目提交到 GitHub。
- 查询中编辑号码不自动覆盖已存清单；编辑已保存号码必须通过“我的”编辑弹窗显式保存。
- 普通进入查询页默认空白，不读取旧记录或“我的”第一组作为默认选号；“清空选号”仅重置当前前后区输入、点选、高亮和提示，不删除持久化号码。
- “我的”每组支持主动带入查询，包括完整复式；带入仅作为一次导航的初始值，之后普通进入查询不得再次恢复，查询修改不得回写原记录。
- “我的”使用独立键 `dlt-my-tickets`，带 `version: 1` 和 `tickets` 数组；每组含稳定 ID、名称、前后区数字数组、可选购买期号和创建/更新时间。
- 首次进入“我的”迁入查询页已保存号码；空清单也要持久化，防止删除后重复迁入。号码备份恢复采用合并去重，禁止覆盖已有记录。
- 存储读取或写入失败须保留原记录并显示错误，不得把保存失败伪装为成功。
- 命中统计使用用户选择的判奖口径并标为“回看”；复式每期只计最高奖级。购买期号未被收录时显示待更新，不能判为未中奖。
- 号码小评复用现有冷热、遗漏和结构计算；复式描述整组候选号，不与单式 5+2 的结构直接评分比较。
- “我的”按总览、单组摘要、逐期开奖、展开详情组织；小评和全部历史默认折叠。逐期对照必须完整显示当期 5+2 号码，深红/深蓝标识命中、浅色标识未命中；查询页左右列表使用相同规则，前后区分别匹配。
- 回看区间支持预设、全部和自定义正整数，并保存浏览器偏好。总览、单组次数、区间最高奖级、逐期列表及小评须使用同一筛选区间；全部历史详情独立标明口径。
- 总次数按“每组号码每期最高奖级”相加，同一期多组命中分别计次；不能把命中组数或全部历史结果混作所选区间次数。

## 判奖规则

- 默认 `latest`：统一使用 2026 版七奖级回看所有历史；`historical` 则按各期开奖期号选择对应规则。
- 历史奖级版本：`07001–19018` 使用六奖级，`19019–26013` 使用九奖级，`26014` 起使用七奖级。选择依据是期号，不是用户录入时间或购买时间。
- 查询与“我的”共用 `dlt-prize-rule-mode` 浏览器偏好；普通导航、主动带入查询、刷新后保持选择。无偏好或偏好无效时默认最新规则。
- 各版本独立配置于 `src/domain/prizeRules`，公共判奖入口为 `src/domain/rules.ts`。结果必须携带规则版本；所有摘要、筛选、指定期号和复式最高奖级都经过同一入口。
- 最新模式只显示七奖级；历史模式按对应数据涉及版本的奖级并集显示。跨版本同名奖级仅按名称汇总，不等同相同命中条件或奖金。
- 切换口径不改变开奖号码、保存号码或命中数量；只重新计算奖级、最高奖、各奖级次数及筛选结果。未中奖情况同样标明所用版本。
- 不从奖级名称推断实际奖金，奖金计算需另有当期官方计奖数据。

## 分析卡片接口

新增卡片必须遵循统一输入输出：

- 输入：已按区间筛选的开奖数据、当前区间配置、全部开奖数据。
- 输出：统计结果、图表数据、摘要文案和娱乐提示。
- 卡片必须能在 `全部 / 近200 / 近100 / 近50 / 近30 / 近10 / 自定义` 区间下工作。
- 卡片组件不得直接读取 JSON 文件，数据由分析页面传入。

## 测试要求

- 数据解析必须覆盖当前 Markdown，可解析出 2869 条记录，最新期号为 `26051`。
- 中奖判定必须覆盖所有奖级和未中奖。
- 判奖需覆盖三个版本各 18 种命中数、两次生效期号边界、默认最新口径、历史奖级并集，以及查询/我的/复式/指定期号的口径一致性。
- 热冷、遗漏、和值、奇偶、大小、连号等统计必须能用固定样本复算。
- 构建前至少运行 `npm run data:validate`、`npm test` 和 `npm run build`。
